# Setup QA Visual Instrument

Set up a project-type-aware screenshot mechanism so agents can take screenshots of the running app and compare them to design references. Called automatically by `/pixel-wizard` when no framework is found, or invoked standalone to set up visual testing for any project.

Outputs `SCREENSHOT_CMD` (mobile projects) and `SCREENSHOT_URL` (web + mobile) to `.env.local`. Web projects use Playwright MCP for screenshots — no `SCREENSHOT_CMD` needed. Mobile projects (Flutter/Android/iOS) still use native CLI commands via `SCREENSHOT_CMD`.

## Arguments

`$ARGUMENTS`

- `/setup-qa-visual-instrument` → Run setup for the current project

---

## Procedure

### Step 1: Detect Project Type

Search for project type markers in the current directory:

| Marker file | Project type |
|---|---|
| `pubspec.yaml` containing `flutter:` key | Flutter |
| `build.gradle`, `build.gradle.kts`, or `AndroidManifest.xml` | Android |
| `*.xcodeproj` directory or `Podfile` | iOS |
| None of the above | Web (default) |

Run glob searches for these markers:
- `glob: pubspec.yaml` → if found, read it and check for `flutter:` section
- `glob: **/build.gradle` or `glob: **/AndroidManifest.xml`
- `glob: **/*.xcodeproj` or `glob: Podfile`

Report detected project type to proceed.

### Step 2: Determine Screenshot Command

Based on detected project type, select the screenshot command:

**Flutter:**
```bash
SCREENSHOT_CMD="flutter screenshot --out=.agent-screenshots/result.png"
```
*Requires: Flutter CLI installed, device/emulator running.*
*Note: Works for both Flutter mobile and Flutter web.*

**Android:**
```bash
SCREENSHOT_CMD="adb exec-out screencap -p > .agent-screenshots/result.png"
```
*Requires: ADB connected to running emulator or device.*

**iOS:**
```bash
SCREENSHOT_CMD="xcrun simctl io booted screenshot .agent-screenshots/result.png"
```
*Requires: iOS Simulator booted.*

**Web (default):**
Web projects use **Playwright MCP** for screenshots — no `SCREENSHOT_CMD` is set.
The agent will use `mcp__playwright__browser_navigate` + `mcp__playwright__browser_take_screenshot` at runtime.
Only `SCREENSHOT_URL` is written to `.env.local` (see Step 3).

### Step 3: Determine Screenshot URL (Web projects only)

Check for existing URL configuration in this order:

1. Read `.env.local` — look for `APP_URL`, `NEXT_PUBLIC_APP_URL`, `VITE_APP_URL`, or `BASE_URL`
2. Read `.env` — same keys
3. Infer from framework defaults:
   - Next.js (`next.config.*` present): `http://localhost:3000`
   - Vite (`vite.config.*` present): `http://localhost:5173`
   - Create React App (`react-scripts` in `package.json`): `http://localhost:3000`
   - Django (`manage.py` present): `http://localhost:8000`
   - Rails (`config/routes.rb` present): `http://localhost:3000`
   - Other: ask Alvi for the URL

If URL cannot be determined automatically, present:

> "What URL should I screenshot for this project?"
> A) I'll enter it manually
> B) It's already in .env.local — tell me the key name

### Step 4: Handle Authentication (WAIT Options)

Present to [USER-NAME]:

**Does the target page require authentication to view?**

> A) No — page is public or dev mode skips auth `✓✓`
> B) Yes, but dev bypass is already configured (e.g., `DISABLE_AUTH=true` in `.env.local`)
> C) Yes — I need to set up auth access

(If C — guide through options:)

> C1) Add a dev auth bypass env var to `.env.local` (e.g., `DISABLE_AUTH=true`) — simplest
> C2) Playwright MCP login flow — agent will navigate to the login page, fill credentials, and proceed to the target page automatically. Ask [USER-NAME] for credentials or env var keys to use.
> C3) Accept limitation — I'll screenshot the login page instead, visual match will be partial

STOP. Wait for [USER-NAME]'s response before writing to `.env.local`.

### Step 5: Write Configuration to `.env.local`

Append the following to `.env.local` (create the file if it does not exist). Do NOT overwrite existing content — append only, or update existing keys if already present.

**For mobile projects (Flutter / Android / iOS):**
```
# Agent Visual Testing Framework — generated by /setup-qa-visual-instrument
SCREENSHOT_CMD={resolved command from Step 2}
SCREENSHOT_URL=  # N/A for mobile
```

**For web projects:**
```
# Agent Visual Testing Framework — generated by /setup-qa-visual-instrument
# Web uses Playwright MCP — no SCREENSHOT_CMD needed
SCREENSHOT_URL={resolved URL from Step 3}
```

For Playwright login flow auth (if Step 4 C2 chosen), also note in a comment:
```
# Auth: Playwright MCP login flow — agent handles login at runtime
```

### Step 6: Create `.agent-screenshots/` and Update `.gitignore`

1. Create the screenshots directory:
```bash
mkdir -p .agent-screenshots
```

2. Check if `.gitignore` exists. If yes, check if `.agent-screenshots/` is already listed. If not listed, append:
```
# Agent screenshot artifacts
.agent-screenshots/
```
If `.gitignore` does not exist, create it with just this entry.

### Step 7: Verify and Report

Run a quick verification for the detected project type:

**Flutter**: `flutter devices` — report connected devices
**Android**: `adb devices` — report connected devices
**iOS**: `xcrun simctl list booted` — report booted simulators
**Web**: Report the configured URL and confirm Playwright MCP will be used for screenshots

Present summary to [USER-NAME]:

```
Visual testing framework configured:
- Project type: {type}
- Screenshot method: {Playwright MCP (web) / SCREENSHOT_CMD (mobile)}
- Screenshot command: {SCREENSHOT_CMD or "N/A — using Playwright MCP"}
- URL: {SCREENSHOT_URL or N/A for mobile}
- Auth: {none / dev bypass / Playwright login flow}
- .agent-screenshots/ created ✅
- .gitignore updated ✅

Ready. Run /pixel-wizard or use SCREENSHOT_CMD directly to take screenshots.
```

**If device/emulator not running** (mobile projects): add a warning:
```
⚠️ No {Flutter device / ADB device / iOS Simulator} detected.
Start your emulator or connect a device before taking screenshots.
```
